# «Платформа» — 3D-сцена: как устроено и как дополнять

Вид «Платформа» — 3D-сцена на three.js (r160, лежит в `assets/vendor/three/`), стилизованная под
плоскую иллюстрацию: каждая грань — свой ровный тон (cel-shading), мягкие тени от солнца, дымка
к горизонту. Данные табло, время суток и панель настроек — общие с видом «Вагон» (`lib/app.js`).

```
main.js ─┬─ engine/      движок: рендер по требованию, камера, свет, тени, небо, сборка кадра
         ├─ stations/    сцены станций: что где стоит, ракурсы, пути, движение поездов
         ├─ prefabs/     объекты сцены по имени type (платформа, путь, фонари, здания, модели…)
         ├─ trains/      вагоны, составы, правила выбора состава, движение
         ├─ weather/     погода
         ├─ style.js     стиль и качество — одно место для настройки вида и нагрузки
         └─ board.js     текст светодиодного табло (HTML поверх сцены)
```

## Координаты

Метры. **x** — поперёк пути (вправо), **y** — вверх от головки рельса, **z** — вдоль пути.
Камера по умолчанию стоит около `z = 0` и смотрит в сторону **−z** (к горизонту).
Пол платформы обычно на `y = 1,1`. Куда смотрит камера по компасу, задаёт `viewAzimuth` сцены —
от него зависит, где на небе солнце и откуда падают тени.

## Сцена станции (блокаут)

Сцена — обычный JS-модуль в `stations/`: данные и комментарии. Пример — `stations/typical.js`,
шаблон с пояснениями — `stations/_template.js`.

```js
export default defineScene({
  id: "tver", name: "Тверь", viewAzimuth: 320,
  cameras: { main: { position: [0, 2.75, 0], yaw: 0, pitch: 0 } },
  shadows: { x: [-18, 18], y: [-1, 14], z: [14, -110] },
  tracks: { main: { x: 4.42, platform: { side: -1, top: 1.1, edge: 2.5 } } },
  objects: [
    { type: "ground" },
    { type: "platform", x: [-4.2, 2.5], top: 1.1 },
    { type: "model", url: "../assets/models/tver.glb", position: [-30, -.3, -20] },
  ],
  traffic: [{ role: "board", track: "main", arrival: { heading: 1, stop: { far: -7.2 } }, departure: { heading: 1, stop: { far: -7.2 } } }],
});
```

Новая станция:
1. скопируйте `stations/_template.js` в `stations/tver.js`, поменяйте `id`, `name`, объекты;
2. в `stations/index.js` добавьте сцену в `SCENES` и, если нужно, станцию в `STATION_SCENES`
   (ID станции — внутренний ID табло РЖД, см. `assets/data/stations.json`);
3. откройте `/platform/?scene=tver&dev=1`: свободная камера, сетка, кнопка «Копировать ракурс».

Сцена собирается так: для каждой строки `objects` вызывается префаб по `type`, мелкие детали
склеиваются в несколько мешей (сотни деталей — пара десятков вызовов отрисовки). Ошибка в одном
объекте не роняет сцену: объект пропускается, ошибка пишется в консоль.

## Префабы (`prefabs/`)

| type | что это | основные параметры |
|---|---|---|
| `ground` | земля до горизонта | `y`, `color`, `size` |
| `skyline` | город у горизонта | `seed`, `count`, `x`, `z`, `height`, `width`, `colors` |
| `hills` | сопки, хребты | `ridges: [{ z, height: [min, max], color, haze }]` |
| `trees` | ряды деревьев | `rows: [{ x, from, to, step, spread }]`, `size`, `trunk`, `colors` |
| `box` | коробка-заготовка | `x`, `y`, `z` (пары от–до), `color`, `cast` |
| `building` | здание-заготовка с окнами | `x`, `y`, `z`, `color`, `facade`, `windows`, `gable`, `roof` |
| `model` | своя модель glTF | `url`, `position`, `rotation` (°), `scale`, `repeat: { count, step }` |
| `platform` | платформа с разметкой | `x`, `top`, `from`, `to`, `edges`, `coping`, `tactile`, `line`, `tiles` |
| `canopy` | навес на колоннах | `x`, `from`, `to`, `height`, `columns: { x: [...], step }`, `lamps` |
| `fence` | ограда | `x`, `base`, `height`, `from`, `to`, `step`, `bar`, `postStep` |
| `lamps` | фонари | `x`, `base`, `height`, `from`, `to`, `step`, `extra`, `toward`, `light` |
| `board` | табло на раме (`screen: true` — живое табло) | `x`, `y`, `z`, `depth`, `base` |
| `stationSign` | табличка с названием станции | `x`, `z`, `width`, `height`, `rotation`, `text` |
| `track` | путь: балласт, шпалы, рельсы | `track` (имя пути), `from`, `to` |
| `catenary` | контактная сеть (опоры, консоли, провода) | `x`, `tracks`, `first`, `span`, `count`, `masts: false`, `feeders` |
| `gantry` | жёсткая поперечина (портал) | `z`, `x`, `height` |
| `footbridge` | пешеходный мост | `z`, `x`, `piers`, `height` |

`from`/`to` — вдоль пути: `from` ближе к камере (больший z), `to` — к горизонту.
Все параметры с пояснениями — в комментарии над каждой функцией в `prefabs/*.js`.

Свой префаб — функция `(params, ctx)` и регистрация:

```js
import { registerPrefab } from "../prefabs/index.js";
registerPrefab("kiosk", (p, ctx) => {
  ctx.solid.box([p.x, p.x + 2], [1.1, 3.6], [p.z, p.z - 3], "wall");   // коробка, отбрасывает тень
  ctx.lamps.push({ position: [p.x + 1, 3.4, p.z - 1.5], range: 6 });     // светит ночью
});
```

Что есть в `ctx` — в шапке `scene/context.js`: склеиваемые коробки (`ctx.solid`, `ctx.flatParts`),
свои меши (`ctx.add`), материалы (`ctx.material`), провода (`ctx.wires`), ореолы огней (`ctx.glows`),
ночные источники света (`ctx.lamps`), пути (`ctx.track`), смена станции (`ctx.onStation`).

## Свои 3D-модели (Blender → glTF)

`{ type: "model", url: "../assets/models/station.glb", position: [x, y, z], rotation: [0, 90, 0] }`

- экспорт glTF 2.0 (`.glb` или `.gltf`), единицы — метры, ось Y вверх (так экспортирует Blender);
- начало координат модели — там, где её ставить (обычно на земле, `y = −0,32`, или на полу платформы, `1,1`);
- из материалов берутся только базовый цвет и текстура: свет, тени, дымку и ночь добавляет сцена,
  так модель сама попадает в стиль; металличность и шероховатость не учитываются;
- материал с `glass` в имени станет стеклом окна (отражает небо, ночью светится), с `night` и Emission —
  светится только ночью (окна, вывески), объект со `smooth` в имени сохранит сглаженные нормали;
- одинаковые копии — `repeat: { count: 8, step: [0, 0, -12] }`: рисуются одним мешем;
- загрузчик glTF подгружается только если в сцене есть модель; сама модель грузится в фоне.

Пример — `assets/models/bench.gltf` (скамейки в типовой сцене).

## Поезда (`trains/`)

- **Вагон** (`trains/cars/*.js`) — объект `{ name, length, gap, build() }`. Пассажирские вагоны
  строятся общим строителем `trains/coach.js` по спецификации: профиль кузова, проёмы окон, ливрея
  на canvas, тележки, ящики, короба на крыше. Ливрея ФПК — из тех же фигур `lib/coach.js`, что и у «Вагона».
- **Состав** (`TRAIN_TYPES` в `trains/index.js`) — список вагонов от головы к хвосту, `":flip"` — вагон
  развёрнут; может быть функцией (грузовой собирается случайно).
- **Правила** (`TRAIN_RULES`) — какой состав показать для поезда с табло: по номеру, маршруту, типу.
  Сцена может добавить свои: `trains: { default: "fpk-long", rules: [{ when: t => …, use: "…" }] }`.

Готовые составы: `fpk-long` (электровоз + 6 вагонов ФПК), `fpk-double` (двухэтажный),
`emu-fast` (скоростной электропоезд), `freight` (грузовой). Посмотреть любой: `?train=fpk-double`.

Свой вагон из Blender (`trains/cars/model.js`):

```js
import { modelCar } from "./cars/model.js";
registerCar("my-coach", modelCar({ name: "Мой вагон", url: "../assets/models/my-coach.glb", length: 24.5, gap: .6 }));
registerTrainType("my-train", { name: "Мой поезд", consist: ["loco-ep", "my-coach", "my-coach"] });
```

Оси модели вагона: z — вдоль кузова от хвостового торца 0 до переднего `length`, y — вверх от
головки рельса. Модель грузится в фоне и сама попадает в тени и перерисовку.

**Движение** (`trains/traffic.js`) задаётся в сцене списком `traffic`:

- `role: "board"` — поезд с табло: прибывает, стоит, уходит. `heading` — куда смотрит голова
  (`1` — к камере, `−1` — к горизонту), `stop.far` / `stop.near` — где встаёт дальний / ближний
  от камеры конец поезда. Тупиковый вокзал: `arrival.heading = 1` (пришёл к упорам за спиной),
  `departure.heading = −1` (стоит локомотивом к выходу и уходит к горизонту) — см. `stations/spb-glavny.js`.
- `role: "passing"` — поезд без остановки (грузовой, транзитный) раз в несколько минут:
  `{ role: "passing", track: "second", type: "freight", heading: -1, speed: 20, every: [240, 720] }`.
  В типовой сцене пример закомментирован — раскомментируйте, чтобы включить.

## Камера и ракурсы

Ракурсы — в `cameras` сцены (формат — в шапке `engine/camera.js`): позиция, цель (`target`) или
`yaw`/`pitch`, фокусное `focal: [kW, kH]` (кадр одинаково собран на любом экране) или `fov`,
`center` — где на экране точка, куда смотрим, поправки для вертикального экрана, реакция на курсор.
Переключение: панель «Ракурс», адрес `?cam=wide`, из кода `engine.rig.go("wide", 2500)`.
Ракурс удобнее всего подобрать в `?dev=1`: «Свободная камера» → WASD/QE + мышь → «Копировать ракурс».

## Погода (`weather/`)

Пресеты — в `weather/presets.js`: покрытие и цвет облаков, сила солнца (и теней), серость неба,
дальность дымки, дождь, снег, мокрая платформа, снег на поверхностях, ветер. Смена — плавная (≈6 с).
Свой пресет: новый ключ в `WEATHER` и подпись в `WEATHER_LABELS` (и ключ — в списке `WEATHER`
в `lib/settings.js`).

Настоящая погода: в `weather/weather.js` есть `fromWmo(code)` — перевод кода погоды WMO
(его отдают, например, open-meteo.com) в ключ пресета. Достаточно получить код для координат
станции и вызвать `weather.set(fromWmo(code))`. Сам запрос в сеть сюда не встроен.

## Стиль и фильтры (`style.js`)

- `quality` — предел pixel ratio, MSAA, разрешение неба, размер карты теней, частоты кадров;
- `light` — коэффициенты света (те же, что были в 2D-виде, поэтому тональность сохранилась);
- `fog` — дымка;
- `filters` — финальный кадр одним проходом (`engine/composite.js`): экспозиция, контраст,
  насыщенность, тёплый/холодный тон, виньетка, постеризация, дизеринг, зерно.
  Новый фильтр — функция в GLSL `composite.js` и параметр здесь.

Материал почти у всего — `toon()` из `engine/materials.js`: цвет или текстура, cel-полосы для
гладких тел (кроны), стекло, свечение ночью, узоры без текстур (плитка, шпалы, рёбра, прутья).

## Нагрузка: рендер по требованию

Кадр рисуется, только когда что-то изменилось (`engine/loop.js`), и по слоям:

| слой | когда перерисовывается | цена |
|---|---|---|
| небо с облаками | пока плывут облака — `quality.skyFps` (12) раз/с | полэкрана, один шейдер |
| сцена | камера, поезд, свет (солнце сдвинулось на 0,1° — раз в ~20 с) | вся геометрия, MSAA |
| тени | сдвинулось солнце, проехал поезд | глубина из «глаз» солнца |
| сборка кадра | после любого слоя; пока идёт дождь или снег — `precipFps` (30) раз/с | один проход |

Когда поезд стоит, в простое рисуется только небо (~12 раз/с, половинное разрешение), сцена и
тени — ни разу; это видно в `?dev=1` («кадров/с»). `quality.skyFps = 0` — облака не плывут,
в простое не рисуется вообще ничего. Бегущая строка табло двигается шагами по 7 px ~12 раз/с.
Когда вкладка или обои скрыты, браузер не вызывает кадры — нагрузки нет.

## Откуда был шум и почему его больше нет

Что давало шум в прежних версиях «Платформы»:

1. **Зерно поверх кадра** (`#grain`, непрозрачность 0,4): статичная крупка по всему изображению,
   особенно заметная в тёмных сценах. Теперь вместо него — дизеринг ±½ ступени (глазу не виден,
   но убирает полосы на градиентах неба); зерно осталось параметром `filters.grain` (по умолчанию 0).
2. **Муар от теней ограды** (2D-версия): тени прутьев с шагом 14 см рисовались линиями в слое
   половинного разрешения и при растяжении давали волнистые полосы на полу. Теперь тень ограды
   считается в шейдере пола аналитически, с фильтрацией по размеру пикселя.
3. **Тонкие провода, консоли и штрихи вдали**: линии тоньше пикселя рассыпались в пунктир и «ползли»
   при движении камеры за курсором. Теперь все тонкие элементы — ленты не тоньше 1 пикселя
   с прозрачностью по настоящей толщине (`engine/wires.js`), дальние огни плавно гаснут.
4. **Повторяющиеся текстуры и мелкая геометрия** (первая 3D-версия): плитка текстурой, повторённой
   ~1250 раз, тысячи прутьев и шпал геометрией, линии в 1 пиксель без сглаживания — муар и мерцание.
   Теперь плитка, шпалы, рёбра вагонов и прутья — формулы, проинтегрированные по пикселю
   (`stripes` в `engine/shaders.js`): вдали они сходятся в средний тон, а не в рябь.
5. **Облака у горизонта**: шум мельче пикселя мерцал. Теперь мелкие октавы шума гасятся,
   когда становятся мельче пикселя.
6. **Края теней «лесенкой» и «акне»**: карта теней сравнивается аппаратно с PCF 4×4 и сдвигом
   по нормали; камера теней привязана к сцене, а не к зрителю, поэтому края теней не плывут.
7. **Совпадающие плоскости** (z-fighting): полосы разметки платформы не перекрываются, у стекла
   и окон — сдвиг глубины. Мерцать нечему.

Чтобы шум не вернулся: не используйте мелкие повторяющиеся текстуры на больших поверхностях
(узор — через `pattern` в `toon()`), тонкие детали рисуйте через `ctx.wires`, не кладите две
поверхности в одну плоскость, производные (`fwidth`) в GLSL считайте до ветвлений.

## Отладка

- `?dev=1` — панель: сцена, ракурс, кадров в секунду по слоям, вызовы отрисовки и треугольники;
  свободная камера, «Копировать ракурс», сетка 1/10 м с осями (красная — x, синяя — z),
  «Смена поезда» (уехать и приехать снова), «Транзит» (пустить грузовой по соседнему пути);
- `?devtest=swap`, `?devtest=pass:second:freight:-1` — то же автоматически при загрузке;
- `window.trainpaper` в консоли — движок, состояние, погода: `trainpaper.weather.set("snow")`,
  `trainpaper.engine.rig.go("wide")`.

## Ограничения

- Светодиодное табло — HTML поверх сцены (текст остаётся чётким и дешёвым), поэтому его не могут
  заслонить объекты сцены; ставьте табло так, чтобы перед ним ничего не было.
- Пути пока только прямые (интерфейс пути — `scene/tracks.js`, кривая добавляется там же).
- После сброса видеодрайвера (потеря WebGL-контекста) страница перезагружается.
