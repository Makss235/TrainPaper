# Движок: как он устроен

Движок лежит в `public/engine/` и ничего не знает о поездах и РЖД: это небольшой 3D-движок
на three.js для «живых иллюстраций» — сцена, которая почти всё время стоит, а двигаются в ней
облака, осадки и отдельные объекты. Вся папка переносится в другой проект целиком
(см. [embedding.md](embedding.md)).

Остальные документы:

|---|---|
| [objects.md](objects.md) | справочник: формат объекта, все компоненты и их свойства, префабы, повторы |
| [scripts.md](scripts.md) | время и поведение: часы симуляции, `update`, `tween`, таймеры, события, скрипты из файлов |
| [post.md](post.md)       | пост-обработка: стек эффектов, свой эффект, LUT |

## 1. Три слоя

```
public/engine/          ДВИЖОК: объекты, компоненты, время, рендер, свет, окружение, погода, пост-обработка.
                        Не содержит ни одной модели и ничего не знает о железной дороге.
public/assets/          СОДЕРЖИМОЕ: модели (models/), префабы (prefabs/), сцены (scenes/), скрипты (scripts/),
                        данные (data/), общие модули моделей и видов (shared/).
public/assets/js/rail/       МОДУЛЬ ПРИЛОЖЕНИЯ: железная дорога — пути, поезда, движение, расписание (rail.md).
public/assets/js/platform/   ЛОГИКА ПРИЛОЖЕНИЯ: табло РЖД на платформе и main.js.
```

Зависимости идут только сверху вниз: приложение знает о движке и содержимом, движок — ни о чём.
Модели не содержат логики (это «как выглядит»), компоненты приложения не строят геометрию сами,
а ссылаются на модели по имени. Поэтому любую модель можно заменить файлом из Blender, не трогая код,
а папку `assets/models/` — очистить: движок продолжит работать (объекты без моделей просто невидимы,
в консоли — понятная ошибка с именем модели).

## 3. Объекты и компоненты

Модель — как в Unity, но проще.

- **GameObject** — объект сцены: имя, теги, флаг `active`, дети и список компонентов.
  Его `object3D` (обычный `THREE.Object3D`) и есть **трансформ**: положение, поворот, масштаб, родитель.
- **Component** — кусочек внешнего вида или поведения, прикреплённый к объекту:
  `Model` (как выглядит), `Light` (светит ночью), `Camera` (это ракурс), `Track` (по пути ездят поезда — модуль приложения)…
  У каждого типа есть **схема свойств** `static props`: тип, значение по умолчанию, пояснение.
  По схеме движок проверяет данные (опечатка в имени свойства → предупреждение в консоли
  со списком правильных), заполняет значения по умолчанию, строит поля в инспекторе и сохраняет
  объект обратно в JSON (только отличия от умолчаний).
- **Scene** — дерево объектов. Загружается из данных (JSONC-файл или объект в коде),
  сохраняется обратно (`scene.toJSON()`).
- **Префаб** — объект в отдельном файле (`assets/prefabs/lamp.jsonc`), на который сцена ссылается
  и поверх которого переопределяет поля.

Камера — тоже объект: ракурс задаётся объектом с компонентом `Camera`, его положение и поворот — это
положение и поворот камеры. Свет фонаря — объект (или часть объекта) с компонентом `Light`.

### Жизненный цикл компонента

| Метод | Когда вызывается |
|---|---|
| `constructor` | свойства уже проверены и лежат в `this.props` |
| `awake()` | объект создан, все компоненты прикреплены, объект добавлен в сцену; здесь строят меши |
| `start()` | вся сцена загружена, ссылки (`ref`, `component`) раскрыты — можно искать другие объекты; может быть `async` |
| `update(dt)` | если объявлен: постоянное поведение, `dt` — секунды симуляции (`static fps`, `static order`) |
| `onEnable()` / `onDisable()` | объект (или родитель) или компонент включили/выключили |
| `onChange(keys)` | свойства поменялись через `component.set({...})` (из кода или инспектора) |
| `onDestroy()` | объект удалён или сцена выгружена: таймеры, переходы и подписки снимаются сами |

Компонент не «крутит кадры» сам. Три инструмента поведения (D2): `update(dt)` — постоянное поведение
(`this.sleep()` / `this.wake()`); `this.tween({...})` — разовый плавный переход с промисом;
`this.wait/every/at` — таймеры и корутины по часам симуляции. Пока ничего из этого не работает, цикл спит.
Подробно — [scripts.md](scripts.md); пример своего компонента — в [objects.md](objects.md#свой-компонент).
`this.animate(tick, fps)` устарел и оставлен на один этап.

### Загрузка сцены — по шагам

`engine.load(url | data)`:

1. ждёт манифест моделей (`assets/models/index.jsonc`: палитра, замены моделей); нет файла — не страшно;
2. **resolve**: подставляет префабы, раскрывает `repeat` (копии со сдвигом);
3. **preload**: скрипты для неизвестных `type` (`assets/scripts/<type>.js`) и всё, что нужно компонентам (модели), —
   сцена появляется целиком, а не по кускам;
4. **instantiate**: создаёт объекты и компоненты, вызывает `awake()` у всех, затем `start()` у всех;
5. событие `sceneLoaded`; применяются `environment` (азимут, тени, погода, таблица неба, свет) и `post` (эффекты);
6. **склейка** (`scene.rebatch()`): неподвижные (`static`, по умолчанию да) меши с одной геометрией
   и одним материалом собираются в `InstancedMesh`. 50 фонарей или 500 деревьев — несколько вызовов
   отрисовки. Если объект подвинули или поменяли его внешний вид, движок пересобирает склейку сам
   (`scene.markDirty`). Объекты с `"static": false` (поезд) не склеиваются.

## 4. Кадр: рисовать только то, что изменилось

Это главная идея движка — обои висят часами, и почти всё это время ничего не меняется.
Кадр собирается из **слоёв**, каждый перерисовывается, только если его пометили (`engine.invalidate(...)`):

| Слой | Что | Когда перерисовывается |
|---|---|---|
| `shadow` | карты теней: солнце и прожекторы с `castShadow` | солнце или прожектор сдвинулись, что-то подвинулось |
| `scene`  | вся геометрия → буфер полного разрешения с MSAA и **текстурой глубины** | что-то изменилось в сцене |
| `sky`    | небо, облака → буфер пониженного разрешения (`skyScale`) | облака плывут (`skyFps`, ~12 раз/с) |
| `fx`     | осадки → свой буфер, проверка по глубине готовой сцены | идёт дождь/снег (`precipFps`, ~40 раз/с) |
| `composite` | один полноэкранный проход: небо + звёзды/луна + сцена + осадки + эффекты стека `engine.post` | любой из слоёв выше; смена параметров эффекта |

Пока идёт дождь, сама сцена **не перерисовывается**: перерисовываются только частицы (дёшево)
и сборка. Когда ничего не движется (анимации выключены, облака стоят), движок не рисует ничего
и не держит ни одного таймера. Кадры идут через `requestAnimationFrame`, поэтому в скрытой вкладке
браузер их не даёт вовсе.

Системы движка регистрируют анимации в цикле с частотой: `engine.loop.animate("key", tick, fps)` — так облака
обновляются 12 раз в секунду, осадки 40, и ни одна анимация не заставляет перерисовывать соседние слои.
Поведение объектов (`update`, `tween`) идёт через планировщик (`core/scheduler.js`) — одну анимацию цикла,
которая снимается, когда никто не бодрствует. Таймеры часов симуляции — один настоящий `setTimeout`
на ближайший таймер, без кадров.

## 5. Цвет и свет

- Все цвета — **экранные (sRGB), как в CSS**. `THREE.ColorManagement` выключен: цвет `"#c4c4bf"` в данных —
  это цвет освещённой поверхности днём. Свет умножает его (плоский иллюстративный стиль).
- Почти всё рисуется одним **cel-материалом** (`render/shaders.js`, `materials.toon({...})`):
  освещённая грань / грань в тени / тень от солнца — несколько плоских тонов; дымка с расстоянием;
  ночные огни; мокрая поверхность в дождь; снег сверху в снегопад; стекло, отражающее небо.
- **Источники света** — компоненты `Light`: точечный (пятно под фонарём), прожектор `spot` (конус с полутенью),
  направленный `directional` (художественная подсветка без спада). Режимы `night` / `always` / `manual`,
  плавное `turnOn(fade)` / `turnOff(fade)` / `setIntensity(v, fade)`. Источники лежат в текстуре данных (до 256);
  шейдер учитывает `quality.maxLights` (32) — видимые в кадре, по вкладу. Список пересобирается только
  при изменениях и заметном сдвиге или повороте камеры.
- **Тени** — у солнца (одна ортографическая карта на область вокруг камеры, `environment.shadows`; PCF 4×4)
  и у не больше `quality.maxShadowLights` (2) прожекторов с `castShadow` (перспективная карта, PCF 3×3).
  Общий класс — `ShadowCaster` (`render/shadows.js`). Карты перерисовываются только по требованию.
  Тени от точечных источников (кубические карты) не делаются.
- **Свет из сцены**: `environment.sun` / `ambient` / `shadows.strength|softness` — множители к расчёту по времени
  («тёплый вечер» без кода). Мягкие пятна света на полу — `GroundGlow`.
- Цвета можно называть: `"platform"` вместо `"#c4c4bf"`. Палитра своя у каждого движка — `engine.palette`:
  манифест моделей (`palette`), `new Engine({ palette: {...} })` или `engine.palette.define({...})`.

## 6. Окружение

`engine.environment` — время суток. Достаточно сказать, где и когда:

```js
engine.environment.setLocation(59.93, 30.36);
engine.time.set(new Date());                      // момент — по часам симуляции; солнце (NOAA) и луна считаются сами
engine.time.scale = 1440;                         // «сутки за минуту»: солнце идёт быстро, облака — как обычно
engine.environment.setAzimuth(135);               // куда по компасу смотрит ось −z сцены
engine.environment.setSun({ azimuth: 200, altitude: 15 });   // или солнце вручную (null — снова по времени)
engine.environment.setSkyTable([[-18, "#050814", "#0b1226"], [3, "#3b61a5", "#f0ac76"], [50, "#2f6cbc", "#9cc3e6"]]);
```

От высоты солнца зависят цвет неба, сила и цвет света, длина теней, звёзды, когда включаются фонари
и окна. Пересчёт идёт, только когда солнце сдвинулось заметно (около 0,1°); пока часы идут, сдвиг проверяется
с частотой по ускорению (×1 — раз в секунду, ×1440 — до 30 раз в секунду). Луна (положение и фаза) — формулы
SunCalc, перенесённые в `environment/celestial.js`, внешние библиотеки не нужны. Таблица неба своя у каждого
движка и может быть задана в сцене (`environment.sky`, например северное небо Мурманска).

`engine.weather` — погода: пресеты `clear`, `partly`, `cloudy`, `overcast`, `rain`, `snow`, `fog`.

```js
engine.weather.set("rain");                       // плавно за 4 с (по реальному времени)
engine.weather.set("rain", { intensity: .35 });   // морось; 1 — дождь, 1,5 — ливень (сила 0…1,5)
engine.weather.set("snow", { ms: 3000 });
engine.weather.set("clear", { instant: true });   // сразу
engine.weather.define("storm", { ...WEATHER.rain, wind: [16, 6], dark: .45 }, "Гроза");  // свой пресет (только у этого движка)
engine.weather.set(fromWmo(code), { intensity: wmoIntensity(code, mmPerHour) });         // настоящая погода
```

Пресет — набор чисел (облачность, сила солнца, дымка, сила дождя/снега, мокрый пол, ветер…; список —
в начале `environment/weather.js`). При смене погоды все числа плавно переходят от старых к новым.
Сила погоды смешивает «переменно → пресет»: небо и свет — быстрее (морось уже пасмурная), осадки и мокрота —
пропорционально силе. Пресеты свои у каждого движка (`engine.weather.table`).

### Осадки в мире

Дождь и снег — частицы **в мире**, в объёме вокруг камеры (дождь — радиус 22 м, снег — 18 м):
дальше их не различить, а дымка заменяет их сама.

- **Под крышей осадков нет.** Сверху рисуется карта высот поверхностей (крыши, навесы, вагоны, пол):
  капля исчезает, долетев до первой поверхности под собой, — там же появляются брызги.
  Поверхности — непрозрачные меши компонентов внешнего вида со свойством `surface: true` (по умолчанию).
  Ту же карту читает cel-материал: **под крышей снег не лежит и пол не мокнет** (стены мокнут и под карнизом).
  Карта — 120 × 120 м, сдвинута вперёд по взгляду камеры, обновляется, только когда камера
  заметно сдвинулась или что-то изменилось в сцене.
- **Без «съезжания».** Положение частиц считается на видеокарте из накопленного смещения: каждый кадр
  `offset += скорость × dt`. Если поменять ветер, меняется скорость, а не положение всего дождя сразу.
- **Плавная смена погоды.** У каждой частицы свой случайный порог: она видна, если плотность выше порога.
  При смене погоды капли появляются и исчезают на своих местах, ничего не сдвигается.
- Скорости близки к реальным: дождь около 9 м/с (штрихи с размытием движения), снег около 1,2 м/с
  с лёгким кружением.
- Частицы рисуются отдельным проходом в свой буфер с проверкой по глубине готовой сцены: за столбом
  капель не видно, а сама сцена не перерисовывается.

Настройки (число частиц, радиус, скорость, размер) — `SETTINGS` в начале `environment/precipitation.js`.

## 7. Камеры

Камеры — объекты сцены с компонентом `Camera`. Движок рисует одной `THREE.PerspectiveCamera`,
а `CameraSystem` ставит её в позу активной камеры.

- **Объектив** задаётся не углом, а фокусным в долях экрана: `focal: [0.6, 1.02]` означает
  `f = max(ширина × 0.6, высота × 1.02)` пикселей. Кадр одинаково собран на любом экране —
  широком мониторе, ноутбуке, телефоне. `center` — где на экране точка, куда смотрит камера
  (горизонт ниже середины и т. п.). Для вертикального экрана — поправки `portrait`.
- `engine.cameras.use("Общий", 2400)` — плавный переход за 2,4 с; `engine.cameras.list()` — все ракурсы.
- `CameraParallax` на том же объекте — камера слегка поворачивается за курсором.

## 8. События

```js
engine.on("sceneLoaded", scene => …);
engine.on("environment", ({ env, celestial, light }) => …);   // пересчитано время суток
engine.on("cameraChanged", camera => …);
engine.on("frame", layers => …);                              // после каждого нарисованного кадра
engine.on("contextRestored", () => location.reload());        // видеокарта сбросила контекст
engine.time.on("timeChanged", ({ reason }) => …);              // часы перевели, ускорили, поставили на паузу
go.on("built", train => …); go.emit("doorOpened", data, { bubble: true });   // события объектов
```

`on` возвращает функцию отписки; у компонента `this.on(target, имя, fn)` снимается сама при удалении.
Компоненты приложения могут посылать свои события через `engine.events.emit("имя", данные)`
(модуль железной дороги шлёт `trainSpawned`, `trainRemoved`, `trainShown`).

## 9. Без шума: правила

Иллюстрация должна быть чистой: без ряби, мерцания и «снега» на мелких деталях. Причины шума
и как движок их обходит:

| Причина | Решение |
|---|---|
| Муар: плитка, шпалы, прутья ограды мельче пикселя вдали | **Узоры в шейдере** вместо геометрии и текстур (`pattern: tiles / sleepers / stripes / bars`): ширина линии сравнивается с размером пикселя (`fwidth`), и вдали узор плавно сливается в средний тон |
| Мерцание тонких проводов, перил | **Тонкие линии** (`Line`, `kit.lines()`): толщина в метрах, но не тоньше пикселя; если тоньше — линия становится прозрачнее, а не пропадает через кадр |
| Z-fighting: две грани в одной плоскости | не кладите грани вплотную: наклейки (полосы, таблички) — с отступом 5–15 мм от поверхности или `material: { offset }` |
| Тени «лесенкой» и «акне» | одна карта теней на ограниченную область, PCF 4×4, сдвиг по нормали; тень ограды — аналитически (`StripeShadow`), без карты теней |
| Полосы на градиентах неба | дизеринг ±½ ступени в сборке кадра (эффект `dither`, всегда последний) |
| Лесенка по краям | MSAA 4× в буфере сцены (`quality.msaa`) |
| Тонкие детали вдали | дымка с расстоянием: дальний план становится силуэтом, а не шумом |

Правила для моделей — в [models.md](models.md#правила-без-шума).

## 10. Нагрузка

- В простое (ничего не движется) — 0 кадров. С облаками — около 12 перерисовок неба в секунду
  в половинном разрешении плюс сборка. В дождь — около 40 проходов частиц плюс сборка; сцена не перерисовывается.
- Все примитивы используют общие единичные геометрии (коробка 1×1×1 и т. д.), материалы кэшируются по
  параметрам — поэтому склейка в `InstancedMesh` работает и между разными моделями.
- Качество — `new Engine({ quality: {...} })` (`render/style.js`, `DEFAULT_QUALITY`):
  `pixelRatio` (предел плотности пикселей, 1,5), `msaa` (4), `skyScale` (0,5), `shadowSize` (2048),
  `maxLights` (32), `maxShadowLights` (2), `spotShadowSize` (1024),
  `maxFps` (60), `skyFps` (12), `precipFps` (40), `precipScale` (1).
- Счётчики — в инспекторе (`?dev=1`): кадров в секунду по слоям, вызовов отрисовки, треугольников, активных
  источников света и карт теней, бодрствующих `update`, переходов и таймеров.

## 11. Как расширять

| Хочу | Как |
|---|---|
| новый вид объекта | модель в `assets/models/` ([models.md](models.md)) + объект или префаб с `Model` |
| новое поведение | скрипт `assets/scripts/<имя>.js` (подключается по соглашению, [scripts.md](scripts.md)) или класс от `Component` + `registerComponent` |
| свою погоду | `engine.weather.define(key, params, label)` |
| другой стиль (резче, теплее, без виньетки) | `new Engine({ style: { filters: {...}, light: {...}, fog: {...} } })` или эффекты сцены `"post"` |
| свой фильтр кадра | класс от `PostEffect` + `registerPostEffect` ([post.md](post.md)) |
| задник (панорама города) | компонент `Backdrop` ([objects.md](objects.md#backdrop--задник)) |
| другой материал | параметры `material` у `Primitive` / `kit.box(..., { material })` (список — `ToonOptions` в `render/materials.js`) |
| модель из Blender | `.glb` в `assets/models/`, имя в `Model.model` ([models.md](models.md#модели-из-blender-gltf)) |

## 12. Публичный API (кратко)

```js
import { Engine, GameObject, Component, Script, registerComponent, PostEffect, registerPostEffect, loadData, parseJsonc, WEATHER } from "/engine/index.js";

const engine = new Engine({ container, paths: { assets, models, prefabs, scripts }, quality, style, palette, pointer, animate });
await engine.load("/scenes/station.jsonc");     // или объект { name, environment, objects: [...] }
engine.find("Табло")                            // объект по имени или пути «Платформа/Фонарь 3»
engine.scene.findByTag("lamp")                  // по тегу
engine.scene.components("Light")                // все компоненты типа
await engine.instantiate({ prefab: "lamp", position: [0, 1.1, -20] })   // создать объект
engine.scene.findComponent("TrainManager")      // первый компонент типа
engine.cameras.use("Общий", 2000)
engine.weather.set("snow", { intensity: 1.3 })
engine.time.set(Date.now()); engine.time.scale = 60
engine.post.add("bloom", { amount: .5 })
engine.tween({ from: 0, to: 1, duration: 2, onUpdate: v => … })   // переход по реальному времени
engine.invalidate("scene")                      // перерисовать после ручных изменений THREE-объектов
engine.project([x, y, z])                       // экранные координаты точки мира
engine.dispose()
```
