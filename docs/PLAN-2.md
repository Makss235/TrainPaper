# План развития движка, этап 2

Скрипты и время, поезда как объекты, расписание, свет с тенями, пост-обработка, окружение.

Этот файл одновременно читает человек и выполняет нейросеть. Формат задачи везде одинаковый —
см. раздел «Как работать с планом».

## 1. Как работать с планом

**Для исполнителя (человека или нейросети):**

1. Перед работой прочитать разделы 2 (инварианты), 3 (принятые решения) и 4 (карта кода).
2. Брать задачи по порядку зависимостей (раздел 5). Одна задача — одно законченное изменение.
3. Перед началом поставить задаче `**Статус:** doing`, после проверки — `done`.
   Если задача отменена — `skipped` и одна строка с причиной в поле «Заметки».
4. Задача готова, только когда выполнены все пункты «Готово, когда» и общая проверка (задача T7.4).
5. Если по ходу появилось решение, которого нет в разделе 3, — дописать его туда (`D<n>`).
   Если решение должен принять владелец проекта — дописать вопрос в раздел 7 и не угадывать.
6. Не делать того, что перечислено в «Вне плана» (раздел 6), без отдельного решения.

**Формат задачи** (поля всегда в этом порядке, необязательные — опускаются):

```
### T<этап>.<номер> — Название
- **Статус:** todo | doing | done | skipped
- **Зависит от:** id задач или «—»
- **Файлы:** какие файлы создать (+) или изменить (~), удалить (−)
- **Что сделать:** шаги
- **API:** как будет выглядеть использование (код)
- **Готово, когда:** проверяемые условия
- **Заметки:** решения по ходу, ссылки
```

## 2. Инварианты (нельзя нарушать)

- **I1. Движок не знает о железной дороге.** В `public/engine/` нет слов «поезд», «вагон», «путь», «РЖД».
  Всё железнодорожное — в слое приложения (`public/assets/js/rail/`, `public/assets/js/platform/`).
- **I2. Без сборки во время работы.** Страницы грузят обычные ES-модули. Node.js нужен только для
  проверок разработчика (`tsc`, `node --test`) и не нужен для запуска сайта.
- **I3. Рисование по требованию.** В простое движок не рисует кадры и не держит `requestAnimationFrame`
  и таймеры. Новое поведение (update, таймеры, свет, эффекты) обязано засыпать, когда ничего не меняется.
  Проверяется счётчиками `?dev=1` (T7.4).
- **I4. Модели — только представление.** Модель (`assets/models/**`) строит геометрию и материалы и отдаёт
  `meta` (данные для логики). В модели нет таймеров, событий, `fetch`, обращений к сцене.
  Модель импортирует только: `three`, публичный API движка (`engine/index.js`), `assets/shared/**`,
  соседние файлы своей папки. Импорт из `assets/js/**` запрещён.
- **I5. Содержимое — данные.** Сцены, префабы, каталоги, расписания — JSONC. Код описывает поведение
  (компоненты и скрипты), данные описывают, что где стоит.
- **I6. Типизация.** Каждый файл движка и приложения начинается с `// @ts-check`;
  `npx -p typescript tsc -p jsconfig.json` проходит без ошибок.
- **I7. Язык.** Имена типов, компонентов и API — английские (как в Unity); комментарии, документация,
  сообщения об ошибках — по-русски.
- **I8. Вид «Вагон» (`public/flat/`) не ломается.** Он не использует движок, но пользуется
  `assets/js/lib/`. После переноса общих модулей (T3.6) он должен работать как раньше.
- **I9. Внешних CDN нет.** Всё, что нужно странице, лежит в проекте.

## 3. Принятые решения

- **D1. `update()` есть, но только по требованию.** Компонент получает `update(dt)`, только если объявил
  этот метод. Он может уснуть (`sleep()`) и проснуться (`wake()`). Пока нет бодрствующих `update`,
  анимаций и таймеров, цикл спит (I3). Частоту можно ограничить: `static fps = 10`.
- **D2. Три инструмента поведения:** `update(dt)` — постоянное поведение; `tween()` — разовый плавный
  переход с промисом; таймеры и корутины `wait/every/at` — по часам симуляции.
  Низкоуровневый `loop.animate()` остаётся только для систем движка (облака, осадки, камера).
- **D3. Часы симуляции.** `engine.time`: текущий момент симуляции (`Date`), ускорение `scale`, пауза.
  Время суток, расписание, движение поездов и таймеры скриптов идут по этим часам.
  Чисто визуальное (облака, осадки, переходы камеры и погоды) — по реальному времени.
- **D4. JS + строгий JSDoc, без TypeScript-сборки.** Публичные типы — в `public/engine/types.d.ts`.
  Переход на TS со сборкой (esbuild) — только если движок станет отдельным пакетом.
- **D5. Скрипты подключаются по соглашению**, как модели: неизвестный `type` компонента →
  файл `assets/scripts/<type>.js` (или замена из `assets/scripts/index.jsonc`). В `main.js` ничего не прописывается.
- **D6. Свет:** `point`, `spot`, `directional`. Тени — у солнца и у ограниченного числа источников
  (`quality.maxShadowLights`, по умолчанию 2). Карты теней перерисовываются только при изменениях.
- **D7. Железная дорога — модуль приложения** `public/assets/js/rail/`: пути, поезд, движение, менеджер,
  расписание. Его можно переносить в другие проекты вместе с движком, но в движок он не входит (I1).
- **D8. Фильтры — подключаемый стек эффектов** (`PostEffect`), а не правка GLSL движка.
- **D9. Астрономия — чистый модуль движка.** Вид «Вагон» берёт положение солнца и луны из
  `engine/environment/celestial.js` (без three.js и DOM) — одна копия формул вместо двух; сам движок «Вагон» не использует.
- **D10. Выключение объекта усыпляет `update` и `tween`, но не таймеры.** `update` вызывается только у активного объекта
  (как в Unity); таймеры и корутины (`wait/every/at`) идут и у выключенного объекта, снимаются только при удалении —
  поэтому мигалка на таймерах может выключать свой же объект.
- **D11. Имя `update` у компонента зарезервировано** под `update(dt)`: метод с этим именем попадает в планировщик.
  Прежние методы приложения переименованы: `DepartureBoard.refresh()`, `TrainManager.updateTrain()`.
- **D12. Инспектор общий.** Модули приложения показывают состояние методом `inspectorPanel()` своих компонентов;
  движок не знает, что это поезда (I1).
- **D13. Пути в данных сцены — от корня содержимого.** Картинки задника, LUT, файл расписания — от папки `assets/`
  (`new Engine({ paths: { assets } })`, `engine.assets.url(path)`).
- **D14. Табло РЖД — строки с открытым концом.** Поезд с табло — строка `depart: null` (стоит, пока строку не уберут)
  с `enter: "standing"` при загрузке и `"now"` при смене поезда; так сохраняется прежнее поведение «один поезд за раз».
- **D15. Строгость типов без `noImplicitAny`** (см. T0.2).
- **D16. Вагон-префаб — явно.** В составе вагон-префаб пишется `cars/<имя>`; иначе — модель и её `meta`. Движок не
  угадывает наличие файла (без лишних 404).
- **D17. Предпросмотр времени суток не останавливает часы.** «Рассвет», «день»… переводят часы плавно (`tween`), дальше
  они идут ×1: поезда и таймеры не замирают, солнце при ×1 почти стоит.

## S1. Время и поведение

### T1.1 — Часы симуляции `engine.time`
- **Статус:** done
- **Зависит от:** T0.2
- **Файлы:** + `public/engine/core/time.js`, + `core/time.test.js`, ~ `core/engine.js`
- **Что сделать:**
  - Часы не тикают сами: момент симуляции вычисляется по запросу,
    `sim = simBase + (realNow − realBase) × scale`. Поэтому они не нарушают I3.
  - `set(date)`, `setScale(k)`, `pause()`, `resume()`, событие `"timeChanged"` (при `set`, смене `scale` и паузе).
- **API:**
  ```js
  engine.time.now          // Date — момент симуляции
  engine.time.ms           // то же в миллисекундах
  engine.time.scale = 1440 // «сутки за минуту»
  engine.time.set(new Date("2026-11-08T05:30:00+03:00"))
  engine.time.pause(); engine.time.resume();
  ```
- **Готово, когда:** тесты: скорость, пауза, `set` во время ускорения, монотонность.

### T1.2 — `update(dt)` по требованию
- **Статус:** done
- **Зависит от:** T1.1
- **Файлы:** ~ `core/component.js`, ~ `core/loop.js`, ~ `core/game-object.js`, + `core/scheduler.js`
- **Что сделать:**
  - Компонент попадает в планировщик, только если в его классе объявлен `update`
    (`proto.update !== Component.prototype.update`).
  - Вызывается для включённого компонента у активного объекта после `start()`.
  - `static fps` — ограничение частоты (по умолчанию — частота кадров); `static order` — порядок вызова.
  - `dt` — секунды **симуляции** (с учётом `scale`; при паузе `update` не вызывается).
    `static realTime = true` — получать реальное время (для визуальных скриптов).
  - `this.sleep()` убирает компонент из планировщика, `this.wake()` возвращает. `onDisable` и `onDestroy` усыпляют сами.
  - Планировщик — одна анимация цикла: есть бодрствующие → тикает, нет → снимается.
  - `update` не обязан вызывать `invalidate()`: `setPosition` и `moved()` уже помечают кадр.
- **API:**
  ```js
  class Blinker extends Component {
    static fps = 4;
  ```
