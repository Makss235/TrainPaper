## 0. Как я понял задачу

1. **Движок отдельно от содержимого.** Код движка не содержит ни одной модели. Всё, что «рисуется»
   (вагоны, платформа, фонари, опоры…), лежит в папке моделей: JS-файлы с процедурными моделями
   или файлы из Blender (`.glb`). Папку можно очистить и заменить своими моделями — движок не сломается.
2. **Сейчас все модели — примитивы** (параллелепипеды, цилиндры): заготовки под замену моделями из Blender.
3. **Объектная модель как в Unity, но проще.** Каждый объект сцены — `GameObject` с `Transform`
   (положение, поворот, масштаб, родитель) и набором компонентов: внешний вид (модель, примитив,
   спрайт, линия), свет, камера, табло, поведение (поезд, движение). Камера — тоже объект.
   Объекты, префабы и сцены описываются данными (JSON) — в файлах или прямо в коде.
4. **Движок переиспользуемый:** ничего не знает о РЖД, встраивается в другой сайт одной строкой,
   с понятным API и документацией.
5. **Станции конечного размера**, а не до бесконечности.
6. **Синяя табличка с названием станции — убрать.**
7. **Осадки — в мире, а не на экране:** капли и снежинки вокруг камеры в ограниченном радиусе,
   под крышей их нет, падают быстрее и реалистичнее, никакого «съезжания» вбок.
8. **Переход между погодой** — переделать (как именно — вопрос 3 ниже).
9. **Упростить движок, где можно**, но с запасом на расширение.
10. **Документация:** как работает движок, как настраивать и добавлять каждый тип объекта,
    как делать модели (JS и Blender), как встроить движок в другой проект.

## 1. Целевая архитектура

Три слоя, зависимости только сверху вниз:

```
public/
├── engine/                     ДВИЖОК — не знает о РЖД; переносится в другой проект целиком
│   ├── index.js                публичный API: Engine, GameObject, Component, registerComponent…
│   ├── core/                   Engine, цикл «рисовать по требованию», Scene, GameObject, Transform,
│   │                           Component, реестр типов, загрузка JSON/JSONC, префабы, события
│   ├── components/             встроенные компоненты: Model, Primitive, Sprite, Line, Light, Glow,
│   │                           Camera, CameraParallax, HtmlScreen, StripeShadow…
│   ├── render/                 cel-материал, тени, тонкие линии, ореолы, сборка кадра и фильтры
│   ├── environment/            время суток (солнце и луна по координатам), небо, облака,
│   │                           погода, осадки в мире
│   ├── assets/                 загрузка моделей: JS-модели, glTF, текстуры; перевод в стиль
│   ├── dev/                    инспектор: объекты, их свойства, свободная камера, сетка, счётчики
│   └── README.md
├── assets/
│   ├── models/                 ВСЕ МОДЕЛИ (представление): *.js — процедурные, *.glb — из Blender
│   ├── prefabs/                объекты из компонентов: «фонарь» = модель + свет + ореол (*.jsonc)
│   └── scenes/                 сцены станций (*.jsonc): что где стоит, камеры, окружение
└── assets/js/platform/         ПРИЛОЖЕНИЕ TrainPaper: табло РЖД, поезда, движение, панель настроек
    ├── components/             RailTrack, Train, TrainTraffic, DepartureBoard — компоненты приложения
    └── main.js
```

**Объект сцены (пример, формат JSONC — JSON с комментариями):**

```jsonc
{
  "name": "Фонарь 1",
  "position": [-3.56, 1.1, -14],
  "rotation": [0, 0, 0],            // градусы
  "components": [
    { "type": "Model", "model": "lamp-post" },                   // внешний вид — модель из assets/models
    { "type": "Light", "kind": "point", "range": 11, "night": true, "offset": [0.9, 5.7, 0] },
    { "type": "Glow", "radius": 1.7, "color": "#ffebbd", "night": true, "offset": [0.9, 5.8, 0] }
  ]
}
```

**Префаб** — такой же объект в отдельном файле; в сцене на него ссылаются и переопределяют поля:
`{ "prefab": "lamp", "position": [-3.56, 1.1, -14], "repeat": { "count": 14, "step": [0, 0, -24] } }`.
Повторы рисуются одним мешем (instancing).

**Способы показать объект:** `Primitive` (коробка, цилиндр, плоскость — для заготовок),
`Model` (JS-модель или `.glb` по имени из реестра или по пути), `Sprite` (картинка лицом к камере),
`Line` (тонкие линии без мерцания — провода), `Glow` (ореол огня), `HtmlScreen` (HTML-элемент на
плоскости в 3D — табло).

## 2. Этапы

      `awake`, `start`, `update`, `onEnable`, `onDisable`, `onDestroy`), схемы свойств компонентов
      (тип, значение по умолчанию, описание) — для проверки данных, документации и инспектора
- [x] `Scene`: загрузка из JSONC-файла или объекта, поиск объектов по имени и тегу, `toJSON()`
- [x] Префабы, переопределение полей, `repeat` → один меш на все копии
- [x] Реестры: компоненты, модели, префабы; понятные ошибки («нет модели X, есть: …»)
- [x] События: `ready`, `frame`, `sceneLoaded`; API для встраивания
- [x] Типизация: JSDoc-типы, `jsconfig.json` + заглушка типов three.js (`types/three.d.ts`); 20 файлов движка

- [x] cel-материал, тени, узоры без ряби, тонкие линии, ореолы, сборка кадра и фильтры → `engine/render/`
- [x] Свет фонарей собирается из компонентов `Light`, а не из ручных списков
- [x] Тени: флаг `castShadow`/`receiveShadow` у внешнего вида, область теней — в настройках сцены
- [x] Буфер глубины сцены (для осадков поверх закэшированной сцены)
- [x] Ревизия и упрощение кода движка: один cel-материал вместо набора, свет из компонентов вместо списков,
      осадки из сборки кадра вынесены в мир, общие единичные геометрии; убраны неиспользуемые флаги;

## 3. Решения, которые я принял сам (скажите, если не так)

- Сцены и префабы — **JSONC** (обычный JSON, но с комментариями `//`): данные отдельно от кода,
  а пояснения остаются. Процедурные модели — **JS**, потому что геометрию удобно строить кодом.
- Имена типов компонентов — английские, как в Unity (`Model`, `Light`, `Camera`); комментарии и документация — по-русски.
- Движок зависит только от three.js (подключается через importmap), без сборки — как сейчас.
- Время суток и погода — системы движка с настройками сцены (`environment`) и API, а не компоненты:
  они общие для всей сцены.
- Табло остаётся HTML поверх сцены (`HtmlScreen`): текст чёткий и дешёвый.
- Табличку станции убираю совсем, вместе с её моделью.

## 4. Ответы на вопросы (8 ноября)

1. **Типизация:** JS + JSDoc-типы, без сборки. В корне — `jsconfig.json`, VS Code подсказывает типы.
2. **Детальные модели:** переносятся в `assets/models/examples/` как отключаемые примеры.
   По умолчанию — примитивы; детальная модель включается одной строкой в `assets/models/index.jsonc`.
3. **Смена погоды:** плавно (3–5 с), без сдвигов — капли и снежинки появляются постепенно на своих местах.
4. **Границы станции:** платформа, навес, ограда, фонари кончаются; пути, контактная сеть и земля уходят к горизонту.
