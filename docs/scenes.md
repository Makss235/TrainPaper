# Сцены станций TrainPaper

Как собрать сцену станции для вида «Платформа»: файл сцены, окружение, камеры, пути, платформы,
движение поездов. Справочник всех компонентов — [objects.md](objects.md), модели — [models.md](models.md).

## Где что лежит

```
assets/scenes/
├── index.jsonc         список сцен и какая сцена у какой станции
├── typical.jsonc       «Типовая платформа» — для станций без своей сцены
├── spb-glavny.jsonc    Санкт-Петербург-Главный: островные платформы под навесами, порталы, 5 путей
├── murmansk.jsonc      Мурманск: сопки, навес у вокзала, 3 пути
└── _template.jsonc     шаблон новой сцены с пояснениями
assets/prefabs/         фонарь, светильник навеса, табло, ограда, скамейка
assets/data/trains.jsonc   составы и правила: какой поезд каким составом показывать
```

## Новая сцена — по шагам

1. Скопируйте `_template.jsonc` в `tver.jsonc`, поменяйте `name`.
2. Добавьте её в `index.jsonc`:
   ```jsonc
   "scenes": [ …, { "id": "tver", "name": "Тверь", "file": "tver.jsonc" } ],
   "stations": { "1146": "tver" }          // ID станции РЖД (assets/data/stations.json) → id сцены
   ```
3. Откройте `/platform/?scene=tver&dev=1` — сцена откроется независимо от выбранной станции,
   с инспектором.
4. Расставляйте объекты: меняйте файл и обновляйте страницу или правьте прямо в инспекторе
   и копируйте JSON кнопкой «Копировать объект».
5. Подберите ракурс свободной камерой и вставьте его кнопкой «Камера в объект».

## Файл сцены

```jsonc
{
  "name": "Тверь",
  "environment": { … },          // окружение: стороны света, погода, тени
  "objects": [ … ]               // объекты (формат — objects.md)
}
```

### `environment`

Кроме азимута, координат, погоды и теней — свет и небо сцены без кода:

```jsonc
"environment": {
  "azimuth": 250, "weather": "rain", "weatherIntensity": 0.4,           // морось
  "shadows": { "x": [-18, 18], "y": [-1, 14], "z": [14, -110], "softness": 1.5, "strength": 0.8 },
  "sun": { "intensity": 1.1, "color": "#ffd9a8" },                       // «тёплый вечер»: множители к расчёту по времени
  "ambient": { "intensity": 0.9, "tint": "#ffe8d0" },
  "sky": [[-18, "#03060f", "#08101f"], [-4, "#16264f", "#4b5f86"], [3, "#3c5f94", "#c7b3c4"], [30, "#3d6fae", "#b8cde0"]]
},
"post": [{ "type": "bloom", "amount": 0.45 }]                             // эффекты кадра этой сцены (post.md)
```

| Поле | Что |
|---|---|
| `azimuth` | куда по компасу смотрит ось −z сцены (вдоль путей от камеры), °: 0 — север, 90 — восток. От него зависит, откуда светит солнце и куда падают тени |
| `weather` | погода по умолчанию, если пользователь не выбрал свою: `clear`, `partly`, `cloudy`, `overcast`, `rain`, `snow`, `fog` |
| `shadows` | где считать тени от солнца: `{ "x": [от, до], "y": [от, до], "z": [от, до] }`, м. Меньше область — чётче тени. Охватите то, что видно вблизи; дальше тени не различить |
| `fog` | дымка: `{ "near": 90, "far": 1600, "max": 0.92 }` — где начинается, где густеет, предел |
| `location` | `[широта, долгота]` — если сцену показывают без данных станции (в TrainPaper координаты дают данные РЖД) |

Как определить `azimuth`: откройте станцию на карте, посмотрите, куда уходят пути от того места, где
стоит камера, и возьмите направление по компасу.

## Система координат TrainPaper

- `x` — поперёк путей (вправо), `y` — вверх, `z` — вдоль путей. Камера у `z = 0` смотрит в сторону `−z`.
- `y = 0` — головка рельса. Пол платформы — `y = 1,1`. Земля — `y = −0,32`.
- Ось пути у платформы обычно `x = 4,42`, край платформы — `x = 2,5`; междупутье — 5,2–5,3 м.
- Глаза человека на платформе — 1,65 м над полом: `y ≈ 2,75`.

## Из чего состоит станция

Типичный набор (см. `typical.jsonc`):

| Объект | Компоненты | Заметки |
|---|---|---|
| камеры | `Camera` + `CameraParallax` | одна с `main: true`; остальные — в панели «Ракурс» |
| земля | `Model environment/ground` | `castShadow: false` |
| дальний план | `environment/skyline`, `environment/hills`, деревья с `repeat` | дымка сама превращает их в силуэты |
| пути | `Model station/track` + `Track` | ось пути (прямые и кривые); модель строит рельсы по ней сама |
| точки остановки | `StopPoint` | где и чем встаёт поезд; `platform: { top, edge, side }` — свет из окон ночью |
| контактная сеть | `Model station/catenary` (`tracks` — оси путей от линии опор) или порталы `station/gantry` + провода с `masts: false` | |
| платформа | `Model station/platform` | `length`, `width`, `edges: ["+x"]` или оба края у островной; `castShadow: false` |
| навес | `Model station/canopy` + префаб `canopy-lamp` с `repeat` | под навесом нет дождя и снега — само |
| фонари | префаб `lamp` с `repeat` | |
| табло | префаб `departure-board` | одно на сцену (элемент `#board` страницы) |
| ограда | префаб `fence` | длину — и у модели, и у `StripeShadow` |
| здания | `Model station/building` или своя `.glb` | фасад с окнами смотрит в +x — поворачивайте объект |
| движение | `TrainManager` + `Schedule` + `RzdBoard` | поезд с табло; проходящие — скрипт `rail/random-traffic` или строки расписания |
| задник | `Backdrop` | панорама города или гор на горизонте (картинка, ночью — огни) |

### Станция конечного размера

Платформа, навес, ограда, фонари — конечной длины: у платформы торцы с пандусами (`ramps`),
за ней виден путь. Пути (`station/track`, `length` по умолчанию 3 км), контактная сеть (`count` опор)
и земля уходят к горизонту — там их скрывает дымка. Ось пути (`Track.points`) начинайте за спиной камеры
(обычно `z = 300`): по ней же поезда уходят «за камеру»; `catenary.back` — провода за спиной.

## Поезда

Поезда — модуль приложения `assets/js/rail/` (подробно — [rail.md](rail.md)).

### Поезд с табло

```jsonc
// путь: ось от z = 300 (за спиной) к горизонту; поезда видны на участке visible (s, м от начала оси)
{ "name": "Путь 1", "position": [4.42, 0, 0], "components": [
  { "type": "Model", "model": "station/track" },
  { "type": "Track", "points": [[0, 0, 300], [0, 0, -3000]], "visible": [260, 1300] } ] },
// поезд встаёт хвостом в 7,2 м от камеры; платформа — слева от пути, если смотреть к горизонту
{ "name": "Платформа 1", "position": [4.42, 0, -7.2], "components": [
  { "type": "StopPoint", "track": "Путь 1", "align": "tail", "platform": { "top": 1.1, "edge": 1.92, "side": "left" } }] },
{ "name": "Движение", "components": [
  { "type": "TrainManager", "pause": 1.8 },
  { "type": "Schedule" },
  { "type": "RzdBoard", "track": "Путь 1", "motion": { "brake": 1.2, "accel": 0.6 },
    "arrival": { "stop": "Платформа 1", "direction": -1, "approach": 420 },
    "departure": { "stop": "Платформа 1", "direction": -1 } } ] }
```

- `direction: −1` — к уменьшению `s`: поезд приходит из-за горизонта к камере; `1` — от камеры к горизонту.
- `align` у точки остановки — чем вставать у отметки: `head`, `tail` или `center`.
- На **тупиковом вокзале** (СПб-Главный, Мурманск) прибывший приходит к упорам за спиной камеры, а отправляющийся
  стоит головой к горизонту у своей точки: `"departure": { "stop": "Отправление", "direction": 1 }`.

Какой поезд показывается, решает приложение по данным табло: прибывший стоит ещё 10 минут,
отправляющийся — до минуты после отправления. При смене поезда текущий уходит, следующий подходит
(подход — с торможением точно к отметке). При загрузке страницы поезд уже стоит.

### Проходящие поезда и расписание

```jsonc
{ "type": "rail/random-traffic", "consists": ["freight"], "tracks": ["Путь 2"], "direction": 1, "every": [240, 720], "speed": [15, 25], "first": 30 }
```

Или по расписанию (пример — сцена `halt.jsonc`): строки `Schedule` с `"action": "pass"` и временем прохода,
`"every"` — повтор. Поля строки — в [rail.md](rail.md#расписание--schedule).

### Составы (`assets/data/trains.jsonc`)

```jsonc
"types": {
  "fpk-long": { "name": "Пассажирский дальнего следования",
                "consist": ["trains/loco-ep", { "model": "trains/coach-fpk", "repeat": 6 }] },
  "emu-fast": { "consist": ["trains/emu-head", { "model": "trains/emu-middle", "repeat": 3 }, "trains/emu-head:flip"] },
  "freight":  { "consist": ["trains/loco-freight", { "random": ["trains/boxcar", "trains/tank"], "count": [18, 32], "groups": 0.22 }] }
},
"rules": [
  { "number": "^[78]\\d\\d", "use": "emu-fast" },       // поля — регулярные выражения по данным поезда
  { "type": "^suburban$", "use": "emu-fast" }
],
"default": "fpk-long"
```

- `consist` — модели вагонов **от головы к хвосту**; `:flip` — вагон развёрнут; `repeat` — несколько
  одинаковых; `random` — случайная смесь (грузовой).
- Правило подходит, если все его поля совпали: `number` («119А»), `from`, `to`, `type`
  (`long` / `suburban` / `other`), `kind` (`arrival` / `departure` / `transit`).
- Своё правило для одной сцены — свойство `rules` у `RzdBoard`.
- Вагон может быть префабом `cars/<имя>` (свои огни, скрипты) — шаблон `assets/prefabs/cars/_template.jsonc`.
- Вагоны склеиваются по данным моделей (`meta.length`, `gap`, `gangway`), поэтому новый тип вагона —
  это только модель с `meta`.

## Параметры адреса для проверки

| Параметр | Что |
|---|---|
| `?scene=murmansk` | показать сцену независимо от станции (`halt` — «Промежуточная станция» с расписанием) |
| `?cam=Общий` | ракурс (имя объекта-камеры) |
| `?train=fpk-double` | этот состав у платформы, какой бы поезд ни был в табло |
| `?weather=rain` | погода; `auto` — настоящая погода станции (сервер, open-meteo.com) |
| `?tod=day\|dawn\|dusk\|night\|cycle` | время суток (предпросмотр); `cycle` — сутки за минуту |
| `?anim=0` | без анимации — для скриншотов |
| `?dev=1` | инспектор: объекты и свойства, свободная камера, сетка, счётчики, время (×60…), поезда, расписание, «Смена поезда», «Транзит» |

## Проверка готовой сцены

- Все ракурсы (панель «Ракурс») на широком экране и на вертикальном (телефон).
- День, закат, ночь (`?tod=`): ночью фонари должны освещать платформу, а окна поезда — светиться.
- Дождь и снег: под навесами осадков нет.
- В инспекторе — счётчики: в простое 0 кадров сцены; вызовов отрисовки — десятки, не сотни.
- В консоли нет предупреждений о неизвестных свойствах и ненайденных моделях.
