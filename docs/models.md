# Модели: как делать и заменять

Модель — это **только внешний вид**: геометрия и материалы, без логики. Все модели проекта лежат
в `public/assets/models/`; движок не содержит ни одной. Объект сцены показывает модель компонентом
`Model` по имени:

```jsonc
{ "type": "Model", "model": "station/lamp-post", "params": { "height": 4.8 } }
```

Модели бывают двух видов:

- **JS-модель** (`station/lamp-post.js`) — геометрия строится кодом из примитивов. Удобно для
  параметрических вещей: платформа любой длины, навес с любым шагом колонн, контактная сеть на N путей.
- **Модель из Blender** (`spb/station.glb`) — файл glTF. Удобно для всего уникального: здание вокзала,
  детальный вагон, скамейка.

Сейчас **все модели по умолчанию — примитивы** (коробки, цилиндры, конусы): заготовки, которые
задают размеры и пропорции. Их можно по одной заменять на модели из Blender, не трогая ни сцены, ни код.

### Правило I4: модель — только представление

Модель строит геометрию и материалы и отдаёт `meta` (данные для логики). В модели **нет** таймеров, событий,
`fetch`, обращений к сцене. Модель импортирует только:

- `three`;
- публичный API движка (`engine/index.js`);
- общие модули `assets/shared/**` — то, что нужно и моделям, и видам (фигуры ливреи `shared/livery/coach-shapes.js`,
  цвета материалов `shared/materials.js`, многоугольники `shared/geom.js`, обрезка `shared/clip.js`);
- соседние файлы своей папки.

Импорт из `assets/js/**` (код приложения) запрещён: проверка — `grep -r "js/lib" public/assets/models` ничего не находит.
Поведение (мигание, движение, огни по ходу поезда) — компоненты и скрипты на объекте, а не код модели.

## Папка моделей

```
assets/models/
├── index.jsonc            манифест: палитра цветов, замены моделей (aliases), данные для glTF
├── environment/           земля, деревья, сопки, город на горизонте
├── station/               платформа, путь, контактная сеть, портал, фонарь, табло, навес, здание, мост, ограда
├── trains/                вагоны и локомотивы (примитивы); _parts.js — общие детали (тележка, окна, торцы)
├── examples/              детальные модели: ливреи ФПК и электропоезда, КС-160 по чертежу — включаются в index.jsonc
└── bench.gltf             пример модели из Blender (glTF)

assets/shared/             общие модули моделей и видов (I4): livery/coach-shapes.js, materials.js, geom.js, clip.js
```

Файлы, имя которых начинается с `_`, — помощники (общие детали), а не модели.

### Как имя превращается в файл

Модель `"trains/coach-fpk"` ищется так:

1. зарегистрирована из кода: `engine.assets.registerModel("trains/coach-fpk", описание)`;
2. замена в манифесте: `"aliases": { "trains/coach-fpk": "my/coach.glb" }`;
3. по соглашению: файл `assets/models/trains/coach-fpk.js`.

Имя с расширением `.glb` / `.gltf` — модель из Blender: `"model": "spb/station.glb"`.

### Замена модели одной строкой

В `assets/models/index.jsonc`:

```jsonc
"aliases": {
  "trains/coach-fpk": "examples/trains/coach-fpk.js",   // детальная модель вместо примитива
  "station/catenary": "examples/catenary.js",
  "trains/loco-ep": "my/ep20.glb"                       // своя модель из Blender
}
```

Все сцены и составы, где есть `trains/coach-fpk`, сразу покажут новую модель.

### Удалить все модели «по щелчку»

Папку `assets/models/` можно очистить целиком. Движок не сломается: объекты, чьих моделей нет,
просто ничего не покажут, а в консоли будет ошибка с именем объекта и модели
(«Модель «station/platform» не загрузилась…»). Манифест тоже необязателен. Свет, камеры, небо, погода
продолжат работать — они не модели.

## JS-модель

Модуль с описанием по умолчанию:

```js
// assets/models/station/lamp-post.js
// Фонарный столб. Начало координат — основание столба; кронштейн смотрит в +x.
export default {
  name: "Фонарный столб",
  params: {
    height: { type: "number", default: 5.2, doc: "Высота столба, м" },
    arm: { type: "number", default: 0.9, doc: "Вылет кронштейна, м" },
  },
  build(p, kit) {
    const g = kit.group(), h = p.height;
    g.add(kit.box([0.12, h, 0.12], { pivot: "bottom", color: "post" }));
    g.add(kit.boxFrom([0, p.arm], [h - 0.12, h - 0.04], [-0.04, 0.04], { color: "post" }));
    g.add(kit.boxFrom([p.arm - 0.22, p.arm + 0.42], [h - 0.18, h - 0.04], [-0.15, 0.15],
      { color: "lamp", material: { emissiveNight: [1, 0.86, 0.56] } }));
    return g;
  },
};
```

| Поле | Что |
|---|---|
| `name` | название (для людей) |
| `params` | параметры с умолчаниями и пояснениями (формат — как у свойств компонентов). В сцене: `"params": { "height": 4.8 }` |
| `meta` | данные для **логики**: длина вагона, где огни, где окна. Объект или функция `(params) => объект` |
| `build(params, kit)` | строит и возвращает `THREE.Object3D`. Вызывается **один раз** на набор параметров; экземпляры — копии с общей геометрией и материалами |

### `kit` — набор для построения

| Функция | Что |
|---|---|
| `kit.box([x, y, z], opts)` | коробка |
| `kit.boxFrom([x0, x1], [y0, y1], [z0, z1], opts)` | коробка по границам — удобнее всего для деталей по чертежу |
| `kit.cylinder(r, h, opts)` / `kit.cone(r, h, opts)` | цилиндр, конус (стоят вдоль y) |
| `kit.sphere(r, opts)` | сфера (по умолчанию — гладкая в два тона: кроны) |
| `kit.plane([x, z], opts)` | плоскость, лежит лицом вверх; `{ uvMeters: true }` — uv в метрах (для узоров) |
| `kit.lines()` | тонкие линии: `.add(a, b, толщина, цвет)`, `.along(...)`, затем `.build()` |
| `kit.glows()` | ореолы огней: `.add(точка, радиус, цвет, { night })`, затем `.build()` |
| `kit.mesh(geometry, opts)` | меш из своей геометрии (`kit.THREE`, `kit.geometry` — помощники) |
| `kit.material(opts)` | материал (из кэша движка) |
| `kit.group(...children)` | группа |
| `kit.rgb(color)`, `kit.rng(seed)` | цвет в `[r, g, b]` (палитра этого движка), случайные числа с зерном |
| `kit.batch()` | склейка деталей с цветом у вершин (`geometry.Batch` с палитрой движка) |

Подсказки VS Code по `kit.*` и параметрам — аннотация типа над описанием модели:

```js
/** @type {import("../../../engine/index.js").ModelDefinition} */
export default { name: "Фонарь", params: { … }, build(p, kit) { … } };
```

Палитра своя у каждого движка; пока модель строится, «текущей» становится палитра строящего движка, поэтому
и `rgb()` из движка, и `new LineBatch()` внутри `build` берут цвета правильно, даже если на странице два движка.

Опции примитивов (`opts`):

| Опция | Что |
|---|---|
| `at: [x, y, z]` | где центр (или низ при `pivot: "bottom"`) |
| `pivot: "bottom"` | ставить низом на `at` |
| `rotation: [x, y, z]` | поворот, ° (YXZ) |
| `color` | цвет: имя палитры, `"#rrggbb"` или `[r, g, b]` |
| `material: {...}` | параметры материала: `glass`, `emissiveNight`, `litNight`, `pattern`, `offset`… ([objects.md](objects.md#параметры-материала)) |
| `slot: "plate"` | слот — сюда приложение подставит свою текстуру |
| `segments` | число граней цилиндра/конуса |

Все примитивы используют **общие единичные геометрии** (коробка 1×1×1, масштабированная), материалы
кэшируются по параметрам. Поэтому одинаковые детали разных объектов движок склеивает в один вызов
отрисовки — не создавайте свои `BoxGeometry` без нужды.

### `meta` и слоты: как модель «разговаривает» с логикой

Логика не должна знать размеры модели «числами в коде» — она читает `meta`. Пример — вагон:

```js
meta: {
  length: 25.5, gap: 0.64,                         // длина и зазор до соседнего вагона, м
  gangway: { half: 0.75, y: [1.2, 3.85] },         // переход-гармошка к соседу
  tailLights: [[-1.15, 1.05], [1.15, 1.05]],       // хвостовые огни у торца z = 0 (если вагон последний)
  headLights: [[-0.9, 1.3, 0.3]],                  // фары (если вагон головной)
  windowSpill: [[3.83, 4.86], …],                  // окна: свет из них ночью падает на платформу
  cab: { … },                                      // кабина (у головных вагонов электропоезда)
}
```

Если модель заменили на glTF, `meta` для неё пишется в манифесте:

```jsonc
"models": {
  "my/coach-fpk.glb": { "meta": { "length": 25.5, "gap": 0.64, "gangway": { "half": 0.75, "y": [1.2, 3.85] } } }
}
```

**Слот** — меш, в который приложение подставит свою текстуру (маршрутная табличка с номером
и маршрутом поезда). В JS-модели: `kit.box(..., { slot: "plate" })`; в Blender — материал с именем
`slot:plate`. В коде: `model.slots("plate")` возвращает такие меши.

Огни вагонов (`tailLights`, `headLights`) становятся компонентами `Glow` с метками `tail-…`/`head-…`
на объекте вагона, свет из окон (`windowSpill`) — пятнами `GroundGlow`; какие горят, решает `TrainLights`
(модуль `rail/`). Если вагону нужно больше, чем модель, — префаб вагона `assets/prefabs/cars/<имя>.jsonc` ([rail.md](rail.md)).

Модель пути `station/track` получает ось от компонента `Track` (`params.path` — точки оси) и строит призму,
шпалы и рельсы по кривой; математику пути модель не знает.

### Оси моделей TrainPaper

| Модели | Начало координат и направление |
|---|---|
| вагоны, локомотивы | `z` от хвостового торца `0` до переднего `length`; `y = 0` — головка рельса; `x = 0` — ось пути |
| платформа, путь, навес, ограда | у ближнего к камере конца, тянутся в сторону `−z` |
| столбы, деревья, здания | середина основания |

Каждый файл модели в первых строках пишет своё начало координат — придерживайтесь его при замене.

## Модели из Blender (glTF)

1. **Масштаб**: 1 единица Blender = 1 метр. Перед экспортом примените масштаб и поворот (`Ctrl+A → All Transforms`).
2. **Оси**: экспортёр glTF переводит Blender (Z вверх) в glTF (Y вверх) сам. Перед модели
   в Blender смотрит в **−Y** (вид спереди, `Numpad 1`) — в движке это **+z**. Вагон в Blender:
   от хвостового торца `y = 0` до переднего `y = −25,5`.
3. **Начало координат** — как у примитива, который заменяете (см. таблицу выше и комментарий в файле модели).
4. **Экспорт**: `File → Export → glTF 2.0`, формат `glTF Binary (.glb)`; включите `+Y Up`,
   `Apply Modifiers`; анимации, камеры и лампы не нужны. Положите файл в `assets/models/` (можно в подпапку).
5. **Подключение**: в сцене — `{ "type": "Model", "model": "spb/station.glb" }`, или замена примитива
   в манифесте — `"aliases": { "station/building": "spb/station.glb" }`.

### Материалы

Материалы Blender **автоматически переводятся в стиль сцены** (cel-материал): из материала берутся
только цвет (Base Color), текстура цвета, прозрачность и свечение. Металличность, шероховатость
и карты нормалей не используются — стиль плоский.

| В Blender | В сцене |
|---|---|
| Base Color | цвет освещённой грани днём (как видите в Blender в режиме Solid/Flat — так и будет) |
| Base Color из текстуры | текстура (держите её небольшой: 512–1024 px) |
| Emission > 0 | светится всегда |
| Emission > 0 и имя материала содержит `night` / `ноч` | светится только ночью (окна, фонари) |
| имя материала содержит `glass` / `стекл` | стекло: днём отражает небо, ночью светится изнутри |
| имя материала `slot:plate` | слот для текстуры приложения (маршрутная табличка) |
| имя **объекта** содержит `smooth` | оставить гладкие нормали (по умолчанию грани делаются плоскими — так лучше смотрится в cel-стиле) |

Пример — `assets/models/bench.gltf` и префаб `assets/prefabs/bench.jsonc`.

### Сколько полигонов

Сцена рисуется не каждый кадр, поэтому запас большой, но разумно держать: вагон — до 20–30 тыс.
треугольников, здание — до 50 тыс. Повторяющиеся модели (фонари, опоры) рисуются одним instanced-мешем —
их число почти не влияет на скорость.

## Правила «без шума»

Стиль — чистая иллюстрация. Чтобы модель не рябила и не мерцала:

- **Нет тонких деталей тоньше ~3 см**, которые видны издалека: провода, тросы, перила, прутья делайте
  тонкими линиями (`kit.lines()`), а не цилиндрами — линии не пропадают «через пиксель».
- **Мелкий повторяющийся рисунок** (плитка, шпалы, гофра, решётка) — узором в материале
  (`pattern: tiles / slats / stripes / bars`), а не геометрией или текстурой: узор вдали плавно
  сливается в средний тон вместо муара.
- **Нет граней в одной плоскости.** Полоса ливреи или табличка поверх кузова — с отступом 5–15 мм,
  или `material: { offset: 1 }`. Иначе грани «дерутся» (z-fighting) и мерцают.
- **Нет огромных тонких плоскостей вплотную к земле** — поднимите на 1–2 см.
- **Крупные плоские грани** лучше мелких деталей: стиль держится на 2–3 тонах и силуэте.
- **Текстуры** — только для того, что нельзя сделать цветом и узором (надписи, ливрея). У текста на
  текстуре — запас по размеру: буквы не мельче 8–10 пикселей текстуры.

## Новая модель — по шагам

1. Создайте `assets/models/<папка>/<имя>.js` (скопируйте похожую модель), в первых строках опишите
   начало координат и направление.
2. Опишите `params` с умолчаниями и пояснениями, постройте геометрию в `build` из `kit`.
3. Поставьте объект с `{ "type": "Model", "model": "<папка>/<имя>" }` в сцену или префаб.
4. Откройте страницу с `?dev=1`: выберите объект в инспекторе и подберите параметры на лету —
   поля строятся по `params`. Готовый JSON — кнопкой «Копировать объект».
